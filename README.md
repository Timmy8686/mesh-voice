# Mesh 多人语音 v2.3.2

当前版本：**v2.3.2**

## 逻辑排查结论与修复（适用性）

### 已确认问题

| 现象 | 根因 | 修复 |
|------|------|------|
| 参与者进房后多出 2 个 ID | `connectTo` / `sync` 在**未接通前**就 `ensureMember`；历史 roster 全量 `forceConnect` 产生幽灵用户 | 仅在 **stream / data open** 后写入成员列表；进房只连房间号 |
| 自动闪退回登录页 | `peer.on('close')` **立即** `returnToLogin`；PeerJS 会误报 close | **延迟 2.5s** 确认 peer 失效后再回登录 |
| 列表人数虚高 | `sendSync` 广播未确认成员 | 只同步已确认/已连通成员 |

### 建议测试步骤（适用性）

1. **创建者**创建房间号并进入；列表应只有「本机」1 人。  
2. **成员 A** 进入同一房间号；双方列表应为 2 人（创建者 + A），无第三、第四幽灵 ID。  
3. **成员 B** 再进；列表 3 人，无重复号。  
4. 成员弱网抖动数秒：**不应**被踢回登录页。  
5. 创建者离开再进：成员保留房间页，数秒内应重新看到创建者。  
6. 主动点离开：回登录且房间号回填。

### 仍存在的环境限制（非逻辑 bug）

- 依赖公共 PeerJS 信令，极端网络下占号/探测可能失败。  
- 无 TURN 时对称 NAT 可能连不上（需自建 TURN）。  
- 浏览器未授权麦克风则无法进房。
